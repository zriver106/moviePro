# 资产管理

> 一条铁律：**资产先行，渲染无创造。**
>
> 分镜切出来的那一刻，它要用的每一个资产就必须已经存在或已被立成工单。
> 到了生成阶段，模型只允许把已冻结的资产按分镜组装 —— 不新建人物、不新建场景、不新建道具。

**状态**：EP001 已跑通端到端（分集卡 → 剧本 → 分镜 → 资产 → 关键帧 → 视频）。
本文档反映实际跑通的架构，不是设计草案。下面每一条约束都有对应的代码和一次真实的失败。

---

## 一、两层，别混

这是整套系统最重要的结构，**当初的设计文档里没有，是跑出来的**。

| 层 | 位置 | 内容 | 给谁用 |
|---|---|---|---|
| **创作真相源** | `projects/<PROJ>/设定集/*.jsonl` | 身份锚点、造型变体、空间地理、道具状态、判定台账 | 人、剧本、分镜 |
| **渲染资产库** | `projects/<PROJ>/assets/<ID>/` | identity_string、参考图、seed、must_keep/avoid | 出图/出片 |

**渲染层是创作层的投影。** 改设定集 → 跑 `scripts/derive_render_assets.py` 重新投影。
**渲染层不许手改** —— 手改一次两层就分家，之后说不清哪个是真的。

### 但投影不是全量覆盖

`derive_render_assets.py` 里的 `OWNED_BY_RENDER` 白名单：

```python
OWNED_BY_RENDER = ("state", "refs", "picked_from", "locked_at", "locked_by",
                   "unlock_log", "anchor_revision")
```

这些是**人在渲染层做的决定**，投影不许碰。
**踩过的坑**：改完设定集重跑派生，5 个刚 `locked` 的资产被打回 `draft`，参考图指针一起丢。

同一条规矩在 `build_storyboard.py` 里也有一份 —— `render` / `state` / `kf_note` 归渲染方，
生成器不覆盖已存在的。**踩过的坑**：我重新生成 shot.yaml 时，硬编码的竖屏默认值
把渲染方改好的横屏 render 段刷回去了，差点渲出 62 秒全片变形。

> **跨会话/跨工具协作时，谁拥有哪个字段必须写死在代码里，不能靠「我们说好了」。**
> 约定挡不住工具 —— 脚本不知道约定，它只知道自己模板里有什么。

## 二、资产的种类与归属

| 前缀 | 类别 | 归哪层 |
|---|---|---|
| `CHAR-` | 角色 | 两层都有。设定集存锚点，渲染层存 identity_string + 参考图 |
| `LOC-` | 场景**视图** | 渲染层的一个 `LOC-` = 设定集里的一个 `VIEW-`，不是一个 `LOCATION` |
| `PROP-` | 道具 | 两层都有 |
| ~~`FIT-`~~ | ~~服装~~ | **不存在。** 服装是角色的造型变体，活在设定集的 `looks.jsonl` 里 |

### 服装为什么不是独立资产

早期设计把服装列为第四类。实际做下来，服装跟着角色走更自然 ——
`LOOK-XIAOJUE-SLEEP`（寝衣散发）和 `LOOK-XIAOJUE-COURT`（朝服束冠）是同一个人的两个造型，
而不是两件独立的东西。

**但造型必须跟着分镜走**：`shot.yaml` 的 `uses.looks` 声明本镜用哪个造型。
**踩过的坑**：渲染层一开始只带角色 id 不带 look，EP001 前九镜（寝衣散发）
被拼成了「束发戴玉冠、靛青常服」—— 开场三秒就穿错衣服，而「散发」正是
观众看出他不像太子的第二个视觉证据。

### 一个空间需要多个朝向的视图

`LOC-` 对应的是**视图**不是地点。同一个房间，机位朝床、朝窗案、朝门是三张不同的板。

**踩过的坑**：EP001 十二镜共用一张「朝门」的寝殿板，
结果九个该拍床的镜头全塌成同一个门厅。

判断标准：**分镜里出现几个明显不同的机位朝向，就要几张板。**

## 三、固定属性 vs 瞬时状态

每个资产的字段分成两半，**永远不许混**：

- **固定属性**（`wardrobe`、`hair_cut`、`face`）—— 冻结后逐字粘贴进每条 prompt，一个字不改
- **瞬时状态**（`wardrobe_state`、`hair_state`）—— 每镜重写，取值必须来自有序状态带

状态带有序，规则：**相邻分镜只准走一格，不准跳、不准倒退。**
倒退读成「另一天」，跨格读成「缺了一个镜头」。已实现为 `bin/asset check` 的硬校验。

## 四、「渲染无创造」的三道机制

### 1. 资产锁

`locked` 之后 identity_string / 参考图 / seed 不可变，改要显式解锁 + 升版本。

**但锁的真正意义不是「人工确认的仪式」** —— 是保证 **Qwen-Image-Edit 有输入可用**。见 §五。

### 2. 依赖门禁

分镜引用的资产没 `locked`，分镜进不了队列。硬拦，不是警告。

```bash
bin/asset check  <PROJ>     # 每个分镜卡在哪一道门、缺哪个资产
bin/asset orders <PROJ>     # 待生产资产工单，按卡住的分镜数排序
```

`orders` 就是出图的优先级 —— 卡住 12 镜的资产排在卡住 1 镜的前面。

### 3. Prompt 拼装器，不是生成器

**生产期一次都不调 LLM。** LLM 只在设计期出现（定 director's book、写 identity_string、切分镜）。

每镜跑一遍 LLM 既是 token 黑洞，又因为每次措辞不同，等于亲手砸掉连续性 ——
**identity_string 最大的敌人就是「换个说法」**。

## 五、参考图是控制面，不是句子

**这是整套系统最重要的一条，早期文档完全没有。**

纯文生图**锁不住身份**。identity_string 再精确，每次生成都是重掷骰子 ——
同一个角色，这一镜和下一镜是两张脸，剪在一起就是换了演员。

正解是 **Qwen-Image-Edit**：拿定稿参考图当**输入**，图 + 文 → 图。

```
有角色的镜头  → TextEncodeQwenImageEditPlus（最多三张参考图：角色 → 场景板 → 道具）
纯道具/空镜   → 文生图就够
```

### 参考图管得了什么，管不了什么

这条边界是实测出来的，写清楚免得再推错：

| 维度 | 归谁管 | 依据 |
|---|---|---|
| 脸、身份 | **参考图** | 文生图每镜重掷骰子，这是整套资产系统存在的理由 |
| 服装、发式、配饰 | **参考图** | prompt 写「月白色常服袍」而图是现代 T 恤，出来的是 T 恤 |
| 光位、色调 | 参考图 + 文字 | 场景板带光位，文字补时刻 |
| 动作、姿态、表情 | **文字** | 图是静态的，动作只能靠文字 |
| **景别、构图** | **谁都管不了** | 见下 |

**景别是个例外，而且我推错过一次。** 造型能被参考图掰过来，我就顺推「想让模型画近景，给它一张近景的参考图」，把角色图裁成头肩喂进去。控制变量测了三档裁切（46% / 40% / 30%）——**输出画面几乎没有变化，始终是头到腰**。

构图由模型的人像先验加画布长宽比决定。`extreme_close` 因此从全剧删除（CD-Y15），`close` 实际渲出来接近中近景。**这是已知偏差，不是 bug**，下游以关键帧为准而不是以 `shot_size` 为准。

裁切现在留着只为身份传递：近景里脸占画面大，参考图里脸也大，五官细节传得更足。

### 造型要有自己的参考图

`refs.ref-body` 拍的是角色的**基底造型**。赵承的基底是穿越前的现代灰 T 恤，蓝沁的基底是寝衣 —— 而全剧 565 镜赵承穿常服、198 镜蓝沁穿日常。

只改 `uses.looks` 和 prompt 里的服装描述**完全无效**，绑进去的图还是 T 恤，出来的还是 T 恤。渲染方逐镜质检抓到皇帝被渲成穿现代黑衬衫的人。

```
assets/<CHAR-x>/ref/v01_ref-body.png                  基底造型
assets/<CHAR-x>/ref/v01_look_<LOOK-ID>.png            非基底造型，各出各的
```

生成办法：`scripts/gen_look_refs_yuan.py` 拿已冻结的 `ref-body` 当输入，用 Edit **只换衣服发式，脸不动**。

三条配套规矩：

1. **`is_base=True` 的造型才共用 `ref-body`。** 这个标记是这条链上最隐蔽的开关 —— 标错等于宣称「这套的图已经有了」，出图脚本跳过、门禁放行、最后绑的是别的衣服。`base_looks()` 里加了一致性校验：基底造型的服装描述要和角色资产的 `wardrobe.outer` 对得上
2. **声明了非基底造型但没有参考图 → 进 `blocked` 列表，不回落**。回落一次太子就穿着 T 恤上朝，而且不报错
3. **发式不是身份锚点，脸才是。** `must_keep` 只装「换了就不是这个人」的东西；把发式写进去，等于宣称这个人换衣服时头发不许变，模型会在两条硬约束之间自己挑一条违反

### 正向 prompt 里一个否定词都不许写

跟模型说「不要 X」，它听见的是「X」。**这条在图像模型的正向通道里同样成立。**

造型定义里写过「腰间束一条同色织锦宽腰带…**无金属扣、无皮革**」，而 `look_text()` 把整句拼进正向 prompt —— 于是渲出黑皮带加金属方扣。删掉那半句，同样的参考图，皮带就不再出现。

排除项只能走**负向通道**（`TextEncodeQwenImageEditPlus` 的 negative 输入，那是分类器自由引导的条件，不是给模型读的文本）。检查正向 prompt 时逐个搜：`不`、`无`、`没有`、`别`、`勿`。

### 声音也是资产

`projects/<剧>/音色/{角色}_ref.wav` —— IndexTTS-2 只吃音频不吃文本描述，所以设定集里的性格锚点（「魏小贤躬身说话语调平缓」）要先变成声音才能用。

真声优先从已渲的**单人有台词镜**抽（两个人在画面里就分不清哪句是谁说的），没渲到的按性格锚点变调派生。`音色/voices.json` 记 `source` 区分两者 —— **派生是权宜不是终态**，不记来源三天后没人分得清。

**抽参考音本身是一道质检**：说话人判错了，文本上「赵啸：陛下…」看着不刺眼，变成声音就露馅（皇帝不会喊陛下）。换一种感官去看同一份数据，能抓到原来那种感官漏掉的错。

### 用 Edit 时，被参考图承担的资产不再往文字里塞 must_keep

**图是约束，文字重复一遍就变成了表演指令。**

**踩过的坑**：文字里写「必须保持…右手食指第二节有一道旧茧」，
模型**把手举起来竖了个大拇指**去展示那道茧。

已实现为 `compose(..., by_ref=[...])`：有参考图的资产，`must_keep` 不进正文。

## 六、写给人的文本 ≠ 写给模型的文本

**今晚十一个 bug 里有六个是同一个根**：我用同一份文本喂人和喂模型。

人读分镜时会自动补上下文、忽略非视觉信息、把表演提示理解成意图。
**模型不会 —— 它忠实执行看到的每一个字。**

| 我写的（给人看） | 模型做的 | 修法 |
|---|---|---|
| 「门外通传声传入」 | **把声源画成一个走进来的人** | 声音整条删掉，声音归音频轨 |
| 「他在等她的反应」 | 加多余动作和表情 | 改成「视线停在一处不动」 |
| 「呼吸没有平复」 | 演成大口喘气 | 改成「肩线仍有起伏」 |
| 「散发遮住半边脸」 | 头发糊住整双眼睛 | **改源头** —— 负向压不过正向的明确指令 |
| 「他的动作停在半途」（末帧） | 画成站着走路 | 末帧必须自足，同时给起始姿态 |
| 「美型化」（负向） | 完全无效 | 换成可指认的实例：`双眼皮/剑眉/宽下颌/磨皮` |

已实现为 `gen_keyframes.py` 的 `VISUALIZE` 表 + 视觉化改写层。
**只作用于喂图像模型这一步，不改分镜原文** —— 分镜要保留那些表述，
它们是给写剧本和渲视频的人看的。

### 两条通用规律

1. **只在正向说「不要 X」不够，负向必须也点名 X。**
2. **模型会把抽象状态词具象成一个物件**（「摩挲得发白」→ 贴了一块像撕掉标签的白补丁）。
   写状态要写它的物理成因。

### 语序按景别变

图像模型前 20 词主导。近景镜头如果先铺一大段空间描述，景别指令被挤到末尾就失效。

- **近景**：先说景别和主体，空间压成一句虚焦背景
- **中远景**：反过来

**踩过的坑**：为了修「跑到室外」在开头加了一大段空间描述，
把「景别 极特写」挤到末尾 —— 要手部特写，出来的是室内全景、手在角落。

## 七、must_keep 的作用域

**`must_keep` 只能包含这个视图里看得见的东西。**

**踩过的坑**（最贵的一个）：场景资产的 `must_keep` 取的是 `location` 的 `fixed_anchors`
（整座府邸的锚点：中轴三重门、正厅老槐、回廊朱漆柱），而这些在寝殿内部一个都看不见。
模型被要求同时满足「寝殿室内」和「画面里得有老槐」，唯一的解就是画那个能看到
门和台阶的门厅 —— **十二个镜头全塌成同一个空走廊**。

现在取的是 `view.orientation.visible_fixed_anchors` + 房间材质。

`must_keep` 还要按**入画范围**裁：只拍手的极特写里塞「窄长脸尖下巴」，
等于要求模型把脸放进来。`shot.yaml` 的 `in_frame` 字段声明画面里到底有什么
（`hands` / `object` / `full`）。

**负向不裁** —— 不管画面里有什么，「不要现代物件」永远成立。

## 八、目录结构

```
projects/<PROJ>/
  short-drama.json              项目配置（drama-skills 格式）：画幅、集数、语言
  项目开发/
    creative-brief.md           创作简报
    story-engine.md             故事引擎（含前提装置契约 DEV-01..06）
    series-arc.md               系列弧线
    episode-map.jsonl           分集卡（真相源）
    episode-map.md              分集卡可读版（渲染产物，改它没用）
  设定集/                        ← 创作真相源
    characters.jsonl  looks.jsonl
    locations.jsonl   location-views.jsonl
    props.jsonl       decisions.jsonl（四类判定台账）
  剧集/<EP>/
    screenplay.md               剧本正文
    screenplay-index.jsonl      派生索引，不反向改正文
    storyboard/shots.jsonl      创作层分镜
  assets/<ID>/                   ← 渲染资产库（投影）
    asset.yaml                  identity_string / 参考图 / seed / must_keep
    ref/v01_<role>.png          定稿参考图（locked 后不可替换）
    ref/_v*_<原因>/             作废候选，归档不删 —— 要能回溯为什么废
    log.md                      出这个资产用过的每一条 prompt
  scenes/<SC>/SH##/              ← 渲染层分镜
    分镜 JSON                    uses / looks / in_frame / render
    kf/v01_kf-first.png         关键帧
    clip/v01_clip.mp4           视频
```

### 命名

目录内用短名（`v01_kf-first.png`），因为 PROJ/SC/SH 已被路径编码。
展开只允许有一处实现（`assets.py:expand_name`）。

`vNN` 单调递增，永不复用、永不覆盖。**批准状态永远不写进文件名** —— 改名会打断所有已写下的引用。

## 十一、命令

```bash
bin/asset ls|new|lock|unlock|orders|check|shots <PROJ>
python3 scripts/build_bible.py                  # 分集卡 → 设定集
python3 scripts/derive_render_assets.py         # 设定集 → 渲染资产库（投影，合并模式）
python3 scripts/build_storyboard.py --all       # 分镜内容 → 创作层 + 渲染层
python3 scripts/gen_asset_refs.py --only <ID>   # 出资产参考板
python3 scripts/gen_keyframes.py --scene SC01 [--shot SH01] [--dry-run]
python3 scripts/epmap_check.py                  # 分集卡校验（交接逐字、装置条款、钩子）
```

### 纪律

> **先 `--dry-run` 看拼装结果，再 `--shot` 单镜验证，最后才批量。**

拼装器的 bug 只能在拼装结果里看，看代码看不出来。今晚四个 bug 是盯着代码读几遍都没发现、
一干跑全冒出来的。要不是这么做，就是几十张废图 + 一集穿错衣服的成片。

### 模型名不要硬编码

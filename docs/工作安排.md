#### T4 补充 · 接缝在哪（2026-08-17 夜查清）

先前以为「skill 出 markdown、我们要 JSON」，**错了**。
`short-drama-storyboard` 产出的是它自己的 JSON/JSONL：

```
剧集/<EP>/storyboard/coverage.json          原文落实表：每个剧本段落一种处理
剧集/<EP>/storyboard/*.jsonl                逐镜记录（shot-template.jsonl 的形状）
设定集/locations.jsonl / location-views.jsonl / characters.jsonl
short-drama.json#/creator_authority/…       创作者授权的视觉方向与制作形态
```

它的镜头记录比我们的严格得多，多出三类我们没有的东西：

| 它有 | 我们有吗 | 值不值得接过来 |
|---|---|---|
| `source_refs`：`owner` + `artifact` + `hash` + `record_id` | 无 | **值** —— 这是全链路溯源，改了源字段能查出谁受影响。我们踩过「派生字段没跟着源字段更新」 |
| `audience_visibility`：本镜允许观众知道什么、用什么手段挡（framing/crop/occlusion/offscreen/focus/timing） | 无 | **值** —— 这是「信息什么时候给观众」的显式管理，我们全靠编剧脑子记 |
| `coverage_role`：primary / intentional_repeat | 无 | 值 —— 能区分「重复镜头」是设计还是偷懒 |
| `information_change`：before → after | 无 | 值 —— 每镜必须改变观众的认知，否则这一镜没有存在理由 |

我们有而它没有的：`render.beats_en` 时间切片、`render.prompt`、
`uses` 资产绑定（它用 `asset_bindings` 带 identity/variant 双引用，更细）。

**为什么现在不写转换器**：`assets/*.jsonl` 里全是 `<sha256>`、`<id>` 占位符，
**没有一份真实产出**。照模板猜着写映射，就是我们自己那条「不凭推测造」的反面 ——
猜错的字段会静默产出看起来合理的错数据。

**解锁条件**：拿一部真实素材跑一遍 `short-drama-storyboard`，
拿到真实的 `coverage.json` 和镜头 jsonl，转换器就是半小时的事。
所以 T4 的真正卡点不是素材本身，是「素材 → 跑一遍 skill → 拿到真样本」。

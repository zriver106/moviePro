# 配音情绪：把情绪词翻译成发声参数

2026-08-17。来源：N次方Ai「四维配音法」+「四维配音进阶 SKILL」两条。

## 一句话

**AI 压根不懂「气恼」该怎么念。** 丢一个情绪词过去，它只能瞎猜。
要把情绪词**翻译成可执行的发声方式**。

这和我们画面侧那条规律**是同一条**，只是换到了音频侧：

```
画面   不写 calm / angry，要写「视线停在一处不动」「抽刀向前突袭」
音频   不写「愤怒」「害羞」，要写「声音压低收紧，每个字像从牙缝挤出来」
```

我们的 `compile_prompts.py` 里早就有 `EMO_RE` 抽象情绪词扫描，
**但它只管画面段**。音频侧一直是空的 —— 分镜里的 `dialogue.delivery`
写的是「咬着牙，手上没停」这类**表演提示**，不是发声参数。

---

## 一之二、完整公式（进阶版补的两截）

只写发声方式还不够。完整公式是：

```
场景  +  人物状态  +  发声方式  +  台词
```

| 段 | 回答什么 |
|---|---|
| **场景** | 角色在哪里，刚刚发生了什么 |
| **人物状态** | 他此刻的**身体和心理**状态 |
| **发声方式** | 音量、语速、停顿、气息、音调（＝下面那四维） |
| 台词 | 原话 |

**同一句台词，场景和状态一换，意思就变了**（视频里的实例）：

```
台词        「你终于来了」

场景 A      一个人在雨里等了很久
发声        声音发颤，语速慢下来，像是忍了很久才终于开口

场景 B      反派等待敌人
发声        声音低沉，语速很慢，最后几个字带一点冷笑
```

作者那句总结是整套方法的根：

> **AI 配音不真实，往往不是台词写得不够好，而是你没有给角色一个说话的理由。
> AI 不是在读文字，而是在表演一个具体时刻。**

这跟我们踩过的一个坑是同一件事：动作从「这镜有没有人在说话」推，
只有两三种状态，做多少变体都是换皮；从「他在说什么、为什么说」推，
才有足够的分辨率。**声音同理。**

## 二、四个维度（当检查清单用）

```
音量 / 声线      压低？放开？收紧？气声？
语速 快慢        偏慢？急促？某几个字拖长？
停顿 节点        在哪个字前停？停多久？
句尾 语调        上挑？下坠？撑不住散掉？
```

**四条都写到，才算翻译完。** 只写「声音压低」是没翻完的。

---

## 三、翻译表（视频里的四个实例，逐字抄）

| 情绪词 | 翻译成发声参数 |
|---|---|
| **愤怒** | 声音压低收紧，把怒火摁在嗓子底下，咬牙切齿，每个字像从牙缝挤出来 |
| **害羞** | 声音细软温润，带淡淡羞涩气音，语速偏慢，句尾微挑带气声 |
| **恐惧** | 嗓音发颤，把恐慌压在喉咙底，带着哭腔，气息又浅又碎 |
| **猜忌** | 慵懒磁性低音，试探感收着柔和着，字尾轻轻上挑但不落，关键位置一停顿 |

## 四、精细到字，不止到句

视频里最值钱的是这个完整示例。**注意它精确到单个字**：

```
原      女主对男主失声痛斥："你让我好失望"

优化后  女主对男主失声痛斥："你让我好失望"，说话时嗓音劈裂失控，
        痛意顶在喉头声线又紧又碎，字音从哭腔里硬挤出来，
        「好」字前猛抽一口气哽住，「失望」二字咬得又重又抖，
        尾音撑不住往下一坠，散成一声带泪的哽咽
```

拆开看四个维度都在：

```
声线   嗓音劈裂失控、又紧又碎、从哭腔里硬挤出来
语速   （隐含在「猛抽一口气」和「咬得又重」里）
停顿   「好」字前猛抽一口气哽住          ← 指名到字
句尾   尾音撑不住往下一坠，散成哽咽      ← 指名收尾怎么收
```

**「哪个字前停」「哪两个字咬重」是这套方法的关键。**
只写「带哭腔」，AI 会均匀地哭一整句，听起来仍然是 AI。

## 五、接进我们的分镜

分镜的 `dialogue` 增加 `voice` 字段，和现有字段分工：

```json
"dialogue": {
  "speaker": "艾琳",
  "text": "三年前火里你丢下我。今天这本书，我替凯尔守。",
  "at": 0.4,
  "delivery": "咬着牙，手上没停",          ← 表演提示，给人看的（画面/口型参考）
  "scene": "废弃神殿，剑压在她最后一层护盾上，她已经连挡三轮",
  "state": "手臂在抖，肺里全是灰；三年的账在这一秒翻上来",
  "voice": "声线压低收紧，气息从胸腔顶出来；语速偏慢一档；
            「丢下我」三字前停半拍，咬字加重；
            句尾「守」字沉下去不上扬，收干净"   ← 发声参数，给 TTS 执行
}
```

`scene` 和 `state` 就是进阶公式的前两截。**它们看起来跟分镜里已有的
`location` 和 `cast[].state` 重复，其实不是**：

```
location        LOC-神殿          给出图用，是地点标识
dialogue.scene  剑压在她最后一层护盾上，她已经连挡三轮   给配音用，是「此刻发生了什么」

cast[].state    站立，横杖硬顶     给出图用，是身体在画面里的姿态
dialogue.state  手臂在抖，肺里全是灰；三年的账翻上来      给配音用，含心理状态
```

**同一个词在两条链上指的不是一件事。** 混用会让配音拿到一个只有姿态、
没有理由的输入 —— 那正是「AI 味」的来源。

**两个字段不能合并**：`delivery` 是给画面和口型看的表演提示，
`voice` 是给 TTS 执行的发声参数。合并之后，
「咬着牙」这种既能当表演也能当发声的词会同时进两条链，各解释一遍。
这是语域铁律的老问题：**同一句话被两个通道读，就会被执行两次。**

## 六、门禁

`compile_prompts.py` 的 `EMO_RE` 只扫英文画面段。音频侧要加一份中文的：

```
禁止只写：愤怒 / 生气 / 害羞 / 恐惧 / 猜忌 / 冷静 / 激动 / 悲伤 / 开心
必须包含：四个维度里至少三个（声线、语速、停顿、句尾）
```

**判据不是「有没有情绪词」，是「有没有翻译成动作」。**
`voice` 里出现「愤怒」不一定错 —— 错的是**只有**「愤怒」。

---

## 七、这条什么时候不适用

**[待验]** 我们的 TTS 链（`tts_dub.py`）目前在 `scripts/legacy_h3/` 里，
是 H3 时代的 IndexTTS-2 参考音克隆。**这套发声参数它吃不吃、吃多少，没验过。**

IndexTTS 是参考音驱动的，音色由参考音决定；
「声线压低」这类指令能不能通过文本影响它，需要一镜对照实验。
换成支持情绪指令的 TTS（或 Seedance 自带音频）才一定生效。

**在验之前，`voice` 字段先写着，不作为硬门禁。**

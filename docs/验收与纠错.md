# 验收与纠错

成片出来之后的流程。目标不是找出所有毛病，而是**分清哪些当场修、哪些回上游** ——
修错层比不修还贵。

---

## 一、机器先筛

机器判不出「画错了」，只判得出「变了没变」。所以机器先筛，人只看机器筛不出的。

```bash
V=.venv/bin/python; P=<剧目>; F=<成片.mp4>

$V scripts/check_cuts.py     $F --threshold 0.4
$V scripts/check_dialogue.py --project $P --ep 1
ffprobe -v error -show_entries format=duration -of csv=p=0 $F
ffmpeg -i $F -vf "fps=1,scale=300:-1,tile=6x5" -frames:v 1 grid.png
```

| 量什么 | 工具 | 抓的是什么 |
|---|---|---|
| 时长 | `ffprobe` | 端点上限静默截断（提交 30 秒回来 15 秒，不报错） |
| 台词 | `check_dialogue` | prompt 里没给台词时模型会自己编，编得挺像 |
| 切镜 | `check_cuts` | 一镜到底有没有真做到 |
| 静止 | 逐秒帧间差 | 哪一秒人站着不动 —— 那一秒的变动量会明显掉下去 |
| 烧字幕 | 抽帧 | 中文台词被印在画面上 |

### 代理指标的适用边界

**代理指标只在「被测的东西是画面里唯一在剧烈变化的东西」时成立。**
一旦别的东西也在剧烈变化，它就开始读那个东西：

| 指标 | 本意量 | 实际会读到 |
|---|---|---|
| 四角像素 ≥250 | 背景是否纯白 | 主体碰到画面角 |
| 场景分数 >0.3 | 切了几刀 | 动作有多快 |
| 场景分数 >0.4 | 切了几刀 | 特效有多大 |
| 按比例取样测肤色 | 脸的颜色 | 头发、盔甲、暗部 |

**指标失效时换指标，不是放宽阈值** —— 放宽会把真问题一起放过去。

配套两条：

```
阈值按内容选        打戏 0.4 / 默认 0.3 / 静态 0.1
零结果先验检测器     扫一遍阈值看单调性（0.4→0 / 0.3→2 / 0.2→6 / 0.1→25），
                    不然「零」和「没测」长得一样
取样类指标要落盘取样图  看图比看数字可靠，靠人记得核对取样位置是靠不住的
```

## 二、人看三类

机器筛完，人只看机器判不出对错的：

```
内容对不对   照分镜逐条核：这一秒该发生的事发生了吗
一致性       同一个人/物在不同秒是不是同一个样
观感         节奏、够不够激烈、有没有哪一下泄气
```

**并排看和逐张看能发现的问题不是一类。** 「近景一半渲成暗调夜景」这种只有
把帧铺成网格才看得见，逐张看每张都挺好。所以第一步永远是出网格图。

**缩太小的图会制造假问题。** 脸、道具这类细节必须裁出来放大再判 ——
340px 缩图上会判出「脸变老、道具没了」这种并不存在的问题。

## 三、已有视频只修复，不重新生成（2026-09-15）

**Andy明确要求：有问题不要重新生成，利用编辑去改问题。** 本规则取代旧的“重渲是最后手段”“换 seed 单镜重渲”和旧版修片分流。

### ① 本机后期编辑

字幕重复、字幕时间轴、剪辑、调色及独立音轨的问题，修改对应后期层并重新导出。重新导出不等于调用模型重新生成。已经烧进画面的文字或混入原声的音乐不能当作独立图层直接删除，需按实际素材选择修复方法。

### ② fal.ai Seedance 2.5 视频编辑

接口依据：[fal.ai API 文档](https://fal.ai/models/bytedance/seedance-2.5/reference-to-video/api)（2026-09-15 核实）。

- 端点：`bytedance/seedance-2.5/reference-to-video`。
- 必须显式传 `task: "editing"`；默认 `reference` 是参考生成，不能拿它冒充编辑。
- `video_urls` 传已有视频，提示词通过 `@Video1` 指向原片，写清目标时间段、具体修改以及需保持的人物、镜头、背景和连续性。遵守项目提示词语域规则。
- 编辑模式自动将 `duration` 和 `aspect_ratio` 设为 `auto`。
- 输入视频每条 1.8–30.2 秒、最大 200 MB；所有输入视频合计不超过 30.2 秒。长成片先截取待修镜头及必要衔接上下文，再编辑并剪回。
- 当前 schema 没有独立时间范围或区域蒙版参数；时间段靠提示词表达，不能承诺范围外画面逐像素不变，也不能宣称只按修改的秒数计费。
- 所有网络调用仍由 `scripts/provider.py` 统一执行。调用前确认实际请求为编辑模式；旧脚本若仅支持参考生成，先修正接入，不能直接拿它执行纠错。

执行顺序：保留原片 → 记录问题时间段与目标 → 编辑现有素材 → 另存版本 → 检查问题是否修好及人物、动作、对白、时长和接缝是否受影响 → 验收通过后替换对应片段。满意的片段沿用原素材。

### ③ 编辑失败的处理

记录实际错误，检查输入限制、素材、提示词和供应商能力，沿编辑路径修复。不得自动切换 `reference`、换 seed 重抽、单镜重渲或整段重新生成；无法修好时保留原片并报告具体阻碍。仅 Andy 后续明确授权重新生成时才可例外。付费调用继续遵守当前授权范围和预算。

上游资料可用于定位根因、完善编辑参考；直接改变剧情的内容仍须走文字评级，不得以更新上游为由自动重新生成已有视频。

**症状在成片，病常在上游。** 常见对应：

| 表面症状 | 真因 | 在哪一层 |
|---|---|---|
| 不够激烈 | 一方没有远程手段，牌面不对等 | 设定 |
| 有个镜头人站着不动 | 那一秒的描述全是状态，没有动词落在身体上 | 分镜 |
| 人物皮肤每处不同 | 定妆照带着环境光，被当成角色固有色 | 资产 |
| 前后两镜像两个地方 | 缺统一底板，同一件家具在两个资产里长得不一样 | 资产 |
| 家具在画面里自己走动 | 参考图锁得住外观，锁不住位置 | 资产 |
| 形态切换没效果 | 只写了形容词，资产没进 `uses` | 分镜 |

**剪辑救不了牌面。** 在成片上反复修是最贵的路。

## 四、判定表

| 问题 | 处理 |
|---|---|
| 可从字幕、剪辑、独立音轨等后期层修复 | 本机编辑并重新导出 |
| 原画面中的人物、动作、背景等问题 | 原视频 + `task: "editing"` |
| 编辑失败或效果不合格 | 诊断并修正编辑路径；无法修好则记录阻碍，不转重新生成 |

**每次修复都要复验，原片和验收记录保留。**

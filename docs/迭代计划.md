## 二、剧本层直接用 webnovel-writer

仓库已经在 `vendor/webnovel-writer/`（v6.2.1，Claude Code 插件）。

```bash
claude plugin marketplace add lingfengQAQ/webnovel-writer --scope project
claude plugin install webnovel-writer@webnovel-writer-marketplace --scope project
python -m pip install -r vendor/webnovel-writer/requirements.txt
```

八个技能：`init / plan / write / review / query / learn / dashboard / doctor`。

产出物和我们的需求对得上：

| 它的产出 | 顶掉我上一版计划里的 |
|---|---|
| `设定集/主角卡.md`、`女主卡.md`、`反派设计.md` | 人物小传（P1.2） |
| `设定集/世界观.md`、`力量体系.md` | 创作基准的世界设定部分 |
| `大纲/卷时间线.md` | 光线时间轴的**故事时间**那一半（P1.1） |
| `大纲/卷节拍表.md` | 情绪曲线（P1.4） |
| `.story-system/MASTER_SETTING.json` | canon 单一事实源 |
| `webnovel-review` | 剧本医生的一部分（我们的 `script_doctor.py` 保留，两者查的东西不同） |

**它自带的两条机制正好补我们的短板：**

1. **`.story-system/` 是唯一事实源，`.webnovel/*` 全是派生只读投影**，
   `projection_log.jsonl` 记录哪个投影失败了。
   我们踩过「派生字段没跟着源字段更新」的坑（`soundscape` 从被重写的
   `action_start` 推出来，结果声景在描述不存在的事），这套投影日志就是答案。
2. **节拍表的中段反转必填，没有要写「无（理由：…）」** ——
   禁止静默省略，和我们的反静默兜底同源。
3. 防幻觉三定律：大纲即法律 / 设定即物理 / 发明需识别。
   第三条就是 chaoge 那套的「剧本事实 / 强推断 / 导演提案」。

### 要先定的一件事：章 ↔ 集的换算

60 秒一集，一章网文 2000–3000 字。**先拿第一卷做标定，不要先定规则。**
判据是：一集能不能承载一个完整的「钩子—翻转—兑现」。
如果一章要拆三集，节拍表就得比现在细一档；如果三章并一集，说明写太散。

这个标定做完之前，别批量生产。

## 三、我们要新写的：一个适配器

`scripts/canon_to_board.py` —— 把 webnovel-writer 的 canon 转成我们的分镜输入。

```
设定集/主角卡.md      →  assets/char/<ID>/spec.md 的「身份」段
大纲/卷时间线.md      →  分镜的 story_time 字段 + 光线状态
大纲/卷节拍表.md      →  分镜的 beats（拍点 + 功能 + 情绪值）
.story-system/        →  资产台账的来源标签
```

**这是唯一的新东西。** 它只做转换，不做创作 —— 创作在上游，渲染在下游。

三条约束：

- **单向**。canon 是源，分镜是派生。分镜里改了不回写 canon，
  要改去改 canon 再重跑。否则两边都成事实源，必然分叉
- **转换要留痕**。每个派生字段记它从 canon 的哪一行来的，
  源变了能查出谁受影响
- **转不出来就报错，不兜底**。查不到某个角色的设定就 `exit 1`，
  不要回落到默认值 —— 我们所有最贵的 bug 都在兜底路径上

## 四、我们要补的三样（都很薄）

### 4.1 视觉基准（webnovel-writer 给不了，它是写小说的）

一个 md 模板，全剧一份，不是每集一份：

```
总体导演方向    一句话
影视参考        主参/补参，并写明借鉴什么、不借鉴什么
摄影系统        画幅、帧率、镜头家族，每个焦段负责什么
光线与曝光      欠曝档位、高光以什么不过曝为准
```

**边界**：chaoge 那套每条后面跟一条禁令（禁止无动机推移、禁止 HDR…），
那些写在**给人看的基准文档**里可以，**不能原样进 prompt** ——
我们验过否定即点名，强先验行为一点名就爆。要进 prompt 得逐条过筛。

### 4.2 空间：平面图 + 站位

`assets/location/<LOC>/plan.png` —— 俯视平面图，标门、窗（决定光从哪来）、
家具朝向、镜头轴线。

站位标注**从分镜自动生成**，不做 GUI。chaoge 那个「AI短剧工具箱」是手工
每镜点，100 集扛不住。我们的站位信息已经在 `cast[].state` 里
（「桌后」「桌前」），配一张位置字典就能画出来。

`scripts/plot_blocking.py`：分镜 + `plan.png` + 位置字典 → 标注 PNG。

> 为什么这一项优先级最高：我们已知 prompt 管不住空间关系。
> chaoge 也不是用 prompt 控的，是先画出几何再让每张图照着画。

### 4.3 场景多机位一次出

我们资产逻辑第 4 条已经写了「一个资产只有一张图，多状态排在同一张图里
一次生成，分开生成必漂」，char 的 24 格 sheet 就是这么做的。
**场景没享受到这条待遇。**

把一个房间的正打／反打／过肩／俯视排进一张图一次生成，按 bbox 裁。
**完全复用 `cells.json` 那套机制，不用新写。**

## 五、要改的（都是加字段，不动骨架）

### 5.1 门禁止血（半天，最先做）

现状：

```
CHAR-莉莉          draft              ready_to_render=True
LOC-OFFICE         ready_for_review   （无此字段）
PROP-墨镜          approved           （无此字段）
```

三种状态值 + 一个只在 char 上有的布尔，`grep -rn "status" scripts/*.py`
**零命中** —— 没有任何脚本读它，资产什么状态都能进渲染。

做三件事：统一状态机（`draft / ready_for_review / approved / blocked`）、
删掉重复的 `ready_to_render`、`gen_kf.py` 和 `render_seedance.py`
前置检查资产必须 `approved`，否则 `exit 1` 并列出卡在哪。

**验收**：故意降级一个资产，渲染必须停下并报出是哪个。
只输出 pass 的门禁和没在跑的门禁没法区分。

### 5.2 分镜加两列

- **`strategy`**：`全新 / 延长优先 / 后期合成`。
  `EP001_v3.json` 已经是 4 个长镜单元 T1–T4 了，方向对，就缺这一列。
  用之前先验证 fal 的 Seedance 有没有对应的「视频延长」能力
- **`seconds` 改成区间** `[14, 18]`，不写定值。
  我们踩过「帧数按估算语速定而不是按配音实际长度定」的坑

### 5.3 `continuity_in` + 交接校验

现在 21/21 有 `continuity_out`，没有 `continuity_in`，**没有任何东西校验
交接被接住了**。补齐并加检查：第 N 镜的 out 必须能在第 N+1 镜的 in 里
找到对应，对不上报错。

典型的静默失败位置：每一步单独看都在正确执行自己的逻辑。

### 5.4 资产门禁按类别分 + 查语义

`check_assets_bg.py` 现在只查白底。扩成：

| 类别 | 规则 |
|---|---|
| char sheet | 白底、格数匹配 `cells.json`、逐格对脸 |
| prop | 单件完整入画、白底、无文字说明 |
| location | 有 `plan.png`、多机位在同一张图内 |
| wardrobe | 非基底造型必须有独立参考图，不许回落 `ref-body` |

并且**查语义不只查尺寸**：莉莉的发尾是不是齐肩、`final-freeze` 格是不是
正面居中 —— 这些现在写在 `known_issues` 里靠人记。

续跑判据从「存在」改「合格」：落盘但没过门禁的重做。

## 八、验收

每一步都要是可测的数：

| 步 | 验收 |
|---|---|
| 2 门禁 | 降级一个资产，渲染停下并报出是哪个 |
| 3 标定 | 一集能承载一个完整的钩子—翻转—兑现 |
| 4 适配器 | canon 里查不到的东西，报错而不是给默认值 |
| 5 平面图 | 一集全部镜头的站位能在图上标出且互不矛盾 |
| 6 交接校验 | 首次跑报出的问题数 > 0（等于 0 说明检查没在跑） |
| 7 多机位 | 跨机位的家具形制目视一致 |

**指标只能证明没退步，证明不了好看。** 前面有过两次全绿被判不能看。
